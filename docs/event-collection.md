# 컨퍼런스·해커톤·밋업 수집

공개 일정 피드와 최근 기사를 같은 날짜·URL 검증 경계로 통과시킨 뒤 `PROPOSED` 후보로 저장한다. 관리자가 공식 일정과 참가 조건을 확인해 승인한 행사만 공개한다.

## 수집 경로

| 소스 | 읽는 데이터 | 용도 |
|---|---|---|
| [Developer Conferences Agenda](https://developers.events/) | 공개 `all-events.json` | 국내외 컨퍼런스 이름·개최일·장소·주제 |
| [Major League Hacking](https://www.mlh.com/events) | 공개 페이지의 `upcomingEvents` | 공식 시즌 해커톤·Global Hack Week 일정 |
| [AWSKRUG](https://www.meetup.com/awskrug/events/ical/) | 주최자가 공개한 iCalendar | AWS 한국 사용자 모임 일정 |
| [Dev Korea](https://dev-korea.com/events) | 주최자 행사 카드의 `time[datetime]`과 공식 링크 | 국내 개발자 밋업·세미나 |
| [GDG Incheon](https://gdg.community.dev/gdg-incheon/) | 공개 페이지의 `upcomingEvents.results` | 국내 GDG의 다음 행사 일정 |
| 국내 주최자 공식 공지 | `verified-korean-events.ts`의 확인된 개최일·장소·근거 URL | 공개 피드가 없는 컨퍼런스·해커톤 보완 |
| 기존 RSS 기사 | 제목·본문 발췌·발행일 | Gemini가 컨퍼런스·해커톤·개발 경진대회·기술 밋업·세미나 후보 추출 |

Agenda 데이터의 저작자는 Aurélie Vache & contributors이며 [CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/)이다. 이 개인 포트폴리오에서는 비상업적으로 이용한다. 원본 일정에서 필드를 추출하고, 날짜와 URL을 정규화하고, 종료된 항목을 제외한다. 각 후보 설명에 저작자·출처·라이선스·변경 내용을 남긴다. MLH는 행사명·날짜·장소·공식 링크만 사용하며 이미지나 소개글을 복제하지 않는다. 행사 상세 페이지는 자동으로 추가 수집하지 않는다. AWSKRUG와 Dev Korea도 행사명·개최일·공식 링크만 추출하며 설명이나 참가자 정보를 복제하지 않는다. ICS가 장소를 제공하지 않으면 서울로 추정하지 않고 대한민국으로만 표시한다. 반복 일정 규칙이나 알 수 없는 시간대는 추정하지 않는다.

## 동작과 실패 처리

- `conferences` CLI는 `DATABASE_URL`만 필수다. Gemini 키가 없으면 공개 피드 수집은 실행하고 기사 분석만 건너뛴다. `all`은 기존 다른 AI 작업 때문에 키가 필요하다.
- 다섯 공개 소스는 병렬로 읽고 소스별 성공·실패를 반환한다. 네트워크/스키마/저장 실패가 있으면 성공한 후보는 유지하고 CLI는 실패 종료 코드로 알린다.
- 정확한 달력 날짜만 저장한다. 종료일이 시작일보다 이르거나 이미 종료됐으면 제외한다. 여러 날 행사는 KST 기준 종료일까지 공개 목록에 남긴다.
- 추적 쿼리와 URL fragment를 제거하되 행사 식별 쿼리는 보존한다. HTTP(S) 이외 URL과 내부 호스트는 거절한다.
- URL 또는 정규화한 행사명+개최일이 같으면 중복을 제외한다. 기존 URL 미상 후보에 공식 URL이 발견되면 해당 행의 URL만 보완한다. 기존 승인·거절 상태는 유지한다.
- 같은 수집 실행에서 공식 공지 확인 목록을 먼저 저장한다. 공개 목록의 축약 정보와 URL이 같으면 확인된 날짜·유형·참가 조건을 유지한다. 기존 DB 행은 이 순서 변경으로 덮어쓰지 않는다.
- 해커톤은 기존 `topics`의 `Hackathon`, 밋업·세미나는 `Meetup`으로 구분한다. 명시된 `Meetup`은 행사명에 포함된 해커톤 단어보다 우선한다. 스키마와 외부 의존성은 추가하지 않는다.
- 공개 행사 탭은 검색과 24개 단위 페이지 이동, 관리자 후보는 검색과 20개 단위 검토를 제공한다. API `limit` 기본값은 50, 상한은 1,000이다. 1,000개 초과 규모에는 서버 페이지네이션이 필요하다.

## 실행

```sh
pnpm --filter @devbrief/api build
node apps/api/dist/cli.js conferences
```

Node 24 이상과 DB 연결 환경변수가 필요하다. Redis를 설정한 상시 API 서버는 매일 00:00 KST, GitHub Actions의 기본 `collect`는 매일 09:00 KST에 이 경로를 호출한다. 두 환경을 함께 운영하면 중복 저장은 차단되지만 피드 요청과 기사 분석이 반복되므로 스케줄 하나를 선택한다.

기존 DB의 `url` 고유 제약은 유지했다. 해마다 같은 URL을 재사용하는 행사는 새 회차로 자동 분리하지 않는다. 공개 피드의 날짜 변경·취소도 이미 저장한 후보에 자동 덮어쓰지 않으므로 승인 전 공식 페이지 확인이 필요하다.

## 2026-09-07 로컬 실행 기록

실제 공개 피드에서 진행 중·예정 후보 897개를 정규화했다(Agenda 827, MLH 70). 중복 10개를 제외하고 로컬 PostgreSQL에 887개를 `PROPOSED`로 추가했다(최초 해커톤 태그 71개 포함). 기존 ACTIVE 5개는 유지했으며 총 892개다. 같은 입력을 두 번째 실행했을 때 신규 저장은 0개, 두 실행 모두 저장 실패 0개였다. 이 수치는 로컬 DB 결과이며 배포 DB 등록이나 공개 승인을 의미하지 않는다. [실행 결과](event-collection-checks.json).

API 전체 테스트 415개, 웹 전체 테스트 351개 및 이후 추가한 행사 탭·독립 페이지 집중 검증을 수행했다.

## 다른 PC·서버에서 실행

수집 코드는 노트북의 절대 경로나 사용자 홈 디렉터리를 참조하지 않는다. Node 24 이상·pnpm 10.16.1과 PostgreSQL(pgvector)을 준비하고 대상 환경에 `DATABASE_URL`을 설정하면 같은 CLI를 실행할 수 있다. `conferences`는 Redis와 Gemini 키가 없어도 공개 피드를 수집한다. 신규 DB는 Prisma 클라이언트 생성과 `pnpm db:migrate:deploy`를 먼저 수행한다.

웹·API를 함께 옮길 때는 `NEXT_PUBLIC_API_BASE`, `FRONTEND_URL`, 관리자 환경변수도 대상 주소에 맞춘다. 기존 데이터는 코드 복사로 이전되지 않는다. 같은 원격 DB를 사용하거나 DB를 별도 백업·복원해야 한다. API Dockerfile과 전체 서비스 배포 절차는 [배포 가이드](../DEPLOY.md)에 있다. 이번 검증은 로컬 환경에서 수행했으며 새 머신에서의 전체 설치·부팅 검증은 포함하지 않는다.

최종 검토에서 `237HackFest`의 소문자 `hackathon` 태그를 공통 표기로 정규화했다. 해커톤 태그는 최종 72개이며 전체 신규 후보 수 887개는 동일하다. 같은 문제를 방지하는 저장 경계 회귀 테스트를 추가했다. 실제 수집 데이터로 홈 행사 탭·독립 행사 페이지·관리자 후보를 320/390/768/1440px에서 검증했다. 검색·페이지 이동·빈 결과 복구와 가로 넘침 검사 12건을 통과했다. [Chromium 검증 결과](event-browser-checks.json).

웹의 국내 판정에는 경기·용인을 포함한 국내 행정구역을 반영했다. 밋업·세미나를 별도 유형으로 검색하고 건수를 확인할 수 있다. 이 작업은 운영 승인이나 배포를 자동으로 수행하지 않는다.

화면 미리보기는 기존 공개 일정에 신규 후보 11개와 정정 내용을 합쳐 국내 15개(컨퍼런스 6·해커톤 1·밋업 8)를 확인한다. 이는 승인 전 후보를 포함한 로컬 검증 데이터이며 운영 공개 건수가 아니다. 운영 DB와 사이트 배포는 변경하지 않았다.

행사 화면의 기본 지역은 전체다. 국내·온라인은 사용자가 선택하는 필터이며, 국내 데이터 보강으로 해외 일정을 제거하지 않는다.

2026년 9월 8일 주최자 원문을 추가 확인해 해커톤 16개를 보완했다. Midnight Korea, Daytona Seoul, Habsida, GWDC, EDTH × D4D, c0mpiled Seoul, TRUST404, Agent Field Trip Incheon, 금천 바이브코딩, PAC 피지컬 AI, 뉴스빅데이터, 그린리모델링, 한국코드페어, BLOCK AI, SoftBank Korea, K-조선이다. 각 레코드의 설명에 공식 링크와 확인일, 참가 자격, 본선·개발·데모데이 구분을 남겼다. 모집 마감일을 개최일로 쓰거나 지역 예선을 별도 대회로 늘리지 않았다. 뉴스빅데이터는 국내 대회이지만 본선 장소가 공개되지 않아 도시나 온라인 여부를 추정하지 않았다.

GDG Incheon은 이번 행사 이후에도 주최자의 공개 예정 목록을 수집한다. 목록의 제목·행사 유형에 해커톤이 명시되지 않으면 밋업으로 분류하며, 소개글의 단순 해커톤 언급만으로 유형을 바꾸지 않는다. Agent Field Trip의 해커톤 분류와 장소는 별도로 검증한 공식 공지 목록이 같은 URL로 먼저 저장한다. 종료일이 목록에 없으면 추정하지 않는다. 상세 소개글과 이미지는 복제하지 않는다.

이미 종료된 K-디지털 트레이닝 대회, 날짜가 확정되지 않은 AI@Home, 임직원 전용 GS 대회는 신규 예정 목록에 추가하지 않았다. 밋업인 Builders & Brews와 Shipaton Seoul도 해커톤 수로 세지 않는다. 이 목록이 국내 해커톤 전체를 빠짐없이 포함한다는 의미는 아니며 공식 공지 보완 목록은 지속적인 확인이 필요하다.

실제 공개 피드 5곳은 모두 응답했고 GDG 예정 행사 1개를 읽었다. 공식 확인 목록과 합쳐 로컬 DB에 신규 해커톤 16개를 `PROPOSED`로 저장했다. 기존 903개 행의 모든 필드가 유지된 것을 트랜잭션 안에서 비교했으며 총 919개가 되었다. 동일 입력 재수집은 신규 0개, 저장 실패 0개였다. GDG는 공식 확인 목록과 중복된 1개를 추가 저장하지 않았다. 운영 DB 승인·배포는 수행하지 않았다.

후보를 포함한 미리보기는 전체 915개, 국내 31개, 국내 해커톤 17개다. 기존 미리보기 899개가 모든 필드까지 보존되었으며 해외 행사 검색도 확인했다. 홈 행사 탭과 독립 행사 페이지를 320/390/768/1440px에서 점검했고 전체 지역 기본값, 국내·온라인 필터, 해커톤·밋업 분리, 가로 넘침 검사 8건을 통과했다. 행사 API 테스트 98개, 웹 행사 탭 테스트 4개, API·웹 빌드와 웹 타입 검사를 통과했다.

### 2026-09-08 운영 DB 반영

사용자의 배포 요청에 따라 Render API가 연결한 Neon 운영 DB를 확인하고 행사 전체를 백업했다. 공식 출처로 확인한 국내 행사 27개(해커톤 17개 포함)를 새로 저장하고 해당 신규 ID만 공개했다. 기존 895개 중 FEConf·카카오의 잘못된 일정과 미확인 DEVIEW 시드 3개만 정정했으며 나머지 892개는 모든 필드를 보존했다. 기존 검토 대기 3개를 일괄 승인하지 않았다.

Serializable 트랜잭션 안에서 보존 검사와 재수집을 수행했고, 재수집 신규 0개·수집 실패 0개를 확인했다. 반영 후 총 922개, 공개 918개, 검토 대기 4개다. 이 기록은 앞선 로컬 검증과 구분되는 실제 운영 DB 결과다. 배포 후보의 API 테스트 469개, 웹 테스트 394개, 전체 타입 검사와 린트, Cloudflare Pages 빌드를 통과했다.
