# 목록에서 읽기 선택으로: 관심 분야 브리핑

## 문제와 변화

이전 홈은 다이제스트, 주요 글, 컨퍼런스, 영상을 차례로 보여줬습니다. 수집 기능은 드러났지만 사용자는 매번 읽을 글을 골라야 했습니다. 개선 후 홈의 첫 행동은 관심 분야 선택이며, 그 조건에 맞는 미열람 글을 최대 3편 제시합니다.

글을 열기 전에 기존 요약을 펼쳐볼 수 있습니다. 요약 확인만으로 읽음 상태를 바꾸지 않으며, 사용자가 글을 열거나 읽음으로 표시할 때 기록합니다. 나중에 읽기는 기존 북마크와 연결되어 검색·정렬 가능한 저장 화면으로 이어집니다.

## 선정 기준과 비용

- 불러온 기사 중 발행 시점이 최근 7일 이내인 미열람 글만 대상으로 합니다. 잘못된 날짜, 미래 발행일, 중복 ID와 같은 원문 URL은 제외합니다.
- 내용이 있는 한 줄 요약이 필요합니다. `기사 URL:` 같은 수집 메타데이터는 요약으로 취급하지 않습니다. 기본 추천에서는 미분류 글을 제외하되, 관심 분야에서 ‘기타’를 직접 선택하면 포함합니다. 전체 기사 목록에서는 계속 찾을 수 있습니다.
- 선택한 관심 분야 중 하나에 해당하면 후보가 됩니다. 분야 분류는 기존 제목·요약·태그 기반 분류기를 재사용합니다.
- 최신순으로 살피면서 서로 다른 출처를 먼저 고릅니다. 출처가 적으면 같은 출처의 남은 글로 최대 3편을 채웁니다.
- 관심 분야는 브라우저에만 저장합니다. 계정, 추가 AI 요청, 새 DB 테이블을 추가하지 않았습니다.

일반 RSS 소스도 블로그 이름을 함께 비교해 서로 다른 블로그를 한 출처로 묶지 않습니다. 관심 분야와 선정 기준은 화면에서 직접 확인하거나 바꿀 수 있습니다.

## 첫 화면과 복구

데스크톱은 왼쪽 관심 분야와 오른쪽 글 목록을 나눕니다. 모바일에서는 관심 분야를 한 줄로 넘겨보게 해 글 제목이 첫 화면에서 보이도록 했습니다. 대표 글 한 편을 강조하고 나머지 두 편은 간결한 목록으로 이어집니다.

조건에 맞는 글이 없으면 모든 분야 또는 이전 글로 이동할 수 있습니다. 저장소가 막혀도 현재 화면의 관심 분야 선택은 동작하며, 기억하지 못했다는 안내를 표시합니다. 번역 제목에는 원문 제목도 함께 표시해 비교할 수 있습니다. 키워드 분류와 요약 존재 여부를 검사하며, 기사 내용이나 번역의 정확성을 보증하는 검수는 아닙니다.

홈은 기사 100개, 행사 미리보기 12개, 영상 미리보기 2개만 조회합니다. 사용하지 않는 종합 다이제스트 요청을 제거하고, 오픈소스와 전체 영상 목록은 해당 탭에 들어갈 때 조회합니다. 성공한 목록은 화면 내 탭 이동에서 재사용하고, 실패하면 이미 받은 내용을 유지하며 재시도할 수 있습니다. AI 모델 비교 코드와 데이터 요청은 비교 영역을 펼칠 때 시작합니다.

## 요약 품질과 번역

무료 번역은 원문 언어를 자동 감지하며, 한국어가 없는 결과나 고유명사 보호 토큰이 깨진 결과는 저장하지 않습니다. 영어 전용 대체 번역기에 태국어·일본어 등을 보내지 않습니다.

무료 요약은 본문 문장을 추출해 번역합니다. RSS의 URL·댓글 수, 첫 글 인사말, 구독 안내를 제외하고 저장된 본문도 재사용합니다. 본문을 확보하지 못하면 제목으로 내용을 만들어내지 않습니다. 기존 정상 Gemini 요약은 무료 폴백으로 덮어쓰지 않으며, 번역 실패나 빈 본문 때문에 정상 요약을 지우지 않습니다. 이 방식은 기사 사실관계 검증이나 전문 편집자의 요약을 대신하지 않습니다.

정기 수집의 `repair-summaries` 대상에는 누락·번역 제공자 오류뿐 아니라 URL 메타데이터와 첫 블로그 인사말로 채워진 요약도 포함합니다.

## 검증

2026-09-10 로딩·콘텐츠 개선은 Node.js 24에서 API 496개·웹 468개 테스트, 전체 타입 검사·Biome 검사·빌드와 Pages 빌드를 통과했습니다. 독립 검토에서 찾은 개행 요약 잘림과 무료 폴백의 기존 Gemini 요약 덮어쓰기는 수정 후 회귀 테스트로 확인했습니다.

초기 브리핑 구현은 Node.js 22에서 웹 테스트 40개 파일·349개 테스트를 통과했습니다. 당시 전체 병렬 실행은 환경 부하로 기존 목록 테스트 2개가 시간 초과되어, 동시 작업 수를 2로 제한해 전체 테스트를 다시 실행했습니다. 애플리케이션 코드의 제한 시간은 변경하지 않았습니다.

```sh
pnpm --filter @devbrief/web test --maxWorkers=2
```

타입 검사와 변경 UI·테스트 파일의 Biome 검사도 통과했습니다. Chromium의 320, 390, 768, 1024, 1440, 2560px 폭에서 가로 넘침과 의도하지 않은 콘텐츠 잘림을 검사했습니다. 관심 분야 선택, 요약 펼치기, 저장, 읽음 표시, 새로고침 후 설정·읽음 복원, 빈 상태의 전체 탐색 연결도 확인했습니다. [브라우저 검사 결과](reading-brief-checks.json)에 실행 범위를 남겼습니다.

## 아직 증명하지 않은 것

추천은 첫 화면에 불러온 데이터 범위에 한정됩니다. 관심 분야는 키워드 분류이며 개인 취향을 학습하는 모델은 아닙니다. 계정·기기 간 동기화와 실기기 Safari 검증은 포함하지 않았습니다. 재방문율 증가나 읽기 시간 절약은 실제 사용자 관찰로 검증해야 하며, 현재 결과만으로 주장하지 않습니다.
