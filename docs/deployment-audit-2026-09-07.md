## 백업과 DB 구조 복구

- Neon `backup-before-recollect-20260907` 브랜치를 생성했다. 자동 삭제 없음, Free 플랜 유지.
- 백업에서 기사 7,053건, 영상 50건, 행사 5건, 기존 migration 2건을 직접 조회했다.
- 운영 DB에 빠져 있던 `Article.summarySource`, `Source.lastFetchedAt`, `Source.lastError` 및 제약을 적용했다.
- 삭제 예정인 미사용 4개 테이블이 모두 비어 있고, 행사 이름·날짜 중복이 없음을 검사한 뒤 기존 migration을 실행했다.
- 과거 요약의 생성 방식을 확인할 수 없어 `legacy`로 보존했다. 기존 migration의 일괄 `gemini` 표기를 그대로 적용하지 않았다.
- 현재 적용된 migration은 5개다. 초기화, 전체 재시딩, 기사 삭제는 하지 않았다.
- `/articles/:id` 및 `/sources`의 P2022/500 오류가 해결됐고 실제 원문 본문 표시를 확인했다.

## 수집 경로 수정

- 매일 09:00 KST의 GitHub Actions 기본 명령을 `collect`로 바꿨다. 공개 RSS, 누락·오류 요약의 무료 추출식 복구, 누락 본문, 레포, 영상, 행사, 브리핑을 처리한다.
- `all`과 `reanalyze`의 Gemini 키 요구는 유지한다. 임베딩은 현재 0건이며 유료 AI 호출을 활성화하지 않았다.
- MyMemory의 500 UTF-8 바이트 제한과 응답 상태·할당량 오류를 검사한다. 번역이 안 되면 원문 발췌를 남기며 기존 한국어 제목을 보존한다. 429 응답에는 재호출 대기 시간을 적용한다.
- 공식 사이트와 채널 메타데이터로 FEConf, NAVER D2, kakao tech를 확인하고 잘못된 초기 채널 ID를 수정했다. 공개 YouTube RSS의 실제 채널 ID 형식을 반영했다. 기존 영상의 요약·챕터·길이·수동 행사 연결은 보존한다.
- 새 영상에 없는 재생 시간을 0분으로 표시하지 않고 `길이 미제공`으로 표시한다. 홈의 영상 조회 범위는 100건으로 확대했다.
- 워크플로의 `tee`가 실패 종료 코드를 가리던 문제를 수정했다. 명시적인 Bash와 pipefail을 사용하며 exit 7 테스트로 실제 전파를 검사한다.

## 남아 있는 운영 제약

- 행사의 공개 승인은 아직 하지 않았다. 관리자 비밀번호·세션 비밀값·API 토큰도 기존대로 미설정이라 관리자 쓰기 기능은 잠겨 있다.
- 우아한형제들 RSS는 GitHub 실행 환경에서 403을 반환한다. 이번 누락분은 보충했지만 다음 자동 실행에서도 이 소스의 실패가 기록될 수 있다. 다른 수집 단계는 계속 실행된다.
- 삭제·차단·유료·짧은 원문은 본문 전체를 가져오지 않는다. 이번 검사에서 본문 666건을 건너뛰었고 기존 발췌·원문 링크를 유지했다.
- 공개 영상 RSS는 채널의 최근 공개 항목을 제공한다. 새 영상의 AI 요약·임베딩·재생 시간은 별도 정보가 없으면 생성한 것으로 표시하지 않는다.
- Pages 웹 배포는 CLI 방식이고 데이터 수집은 GitHub Actions다. 웹의 Git 푸시 자동 배포는 별도 설정이다.
- 북마크와 읽음 상태는 브라우저의 주소별 localStorage이므로 Vercel과 Pages 사이에 자동 이전되지 않는다.
